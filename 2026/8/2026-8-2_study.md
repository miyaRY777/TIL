# 今日理解できたこと

## クロージャとは

クロージャとは、**内側の関数が、自分が定義された場所にある外側の変数とのつながりを維持する仕組み**。

クロージャは関数だけではなく、次の組み合わせとして考える。

```text
内側の関数
+
その関数が作られた場所の変数を参照できる環境
```

## 共通例

```javascript
function createCounter() {
  let count = 0;

  return function increment() {
    count++;
    return count;
  };
}

const counter = createCounter();

console.log(counter()); // 1
console.log(counter()); // 2
```

`increment` の中には `count` の宣言がないが、外側の `createCounter` で宣言された `count` を使用できる。

さらに、`createCounter()` の実行が終了したあとも、返された `increment` 関数は `count` を使い続けられる。

## 仕組み

### レキシカルスコープ

どの変数を参照できるかは、関数が「どこから呼ばれたか」ではなく、**どこに定義されたか**によって決まる。

### レキシカル環境

レキシカル環境は、その場所で利用できる変数や、外側の環境へのつながりを管理する。

```text
createCounterのレキシカル環境
├── count = 0
├── increment = 関数
└── 外側の環境への参照
```

`increment` の環境で `count` が見つからない場合、外側の `createCounter` の環境を探して `count` を見つける。

### 値ではなく変数とのつながりを保持する

クロージャは、作られた時点の値をコピーして保存する仕組みではない。同じ `count` とのつながりを維持し、その変数を更新する。

```javascript
counter(); // countが0から1になる
counter(); // 同じcountが1から2になる
```

## `return increment` と `return increment()` の違い

```javascript
return increment;
```

`increment` 関数そのものを返す。

```javascript
return increment();
```

`increment` をその場で実行し、その実行結果を返す。

今回の例では、外側でも関数を使い続けるため、関数そのものを返している。

## `createCounter()` を複数回呼び出した場合

```javascript
const counterA = createCounter();
const counterB = createCounter();

console.log(counterA()); // 1
console.log(counterA()); // 2
console.log(counterB()); // 1
```

`createCounter()` を呼び出すたびに、新しい `count` が作られる。`counterA` と `counterB` は別々の `count` を参照するため、状態を共有しない。

## クロージャが必要な理由

* 呼び出し後もカウンターなどの状態を保持できる
* 変数を外部から直接変更されないようにできる
* 税率などの設定を覚えた関数を作れる
* データと、そのデータを操作する処理をまとめられる

## 主な使用例

* カウンター
* イベントハンドラー
* 税率や表示形式などの設定を保存する関数
* 外部から直接操作できない変数を持つ処理

## 注意点

* 大きなデータを必要以上に参照し続けると、メモリ使用量に影響する場合がある
* `var` を使ったループでは、複数の関数が同じ変数を共有する場合がある
* クロージャを何重にも作ると、どの変数を参照しているのか追いにくくなる
* 複雑になる場合は、オブジェクト、クラス、モジュールなどの設計も検討する
