# 今日理解できたこと

## Working Treeとは

Working Treeは、現在実際にファイルを編集している作業場所のこと。

例えば、次のようなファイルを編集している場所がWorking Treeに当たる。

```text
index.html  （編集中）
app.js      （編集中）
README.md   （未変更）
```

`app.js`を編集した直後の変更内容は、まだWorking Treeにある状態になる。

## Staging Areaとは

Staging Areaは、次のコミットに含めたい変更内容を一時的に登録しておく場所のこと。

Working Treeにある変更を`git add`すると、その時点の内容がStaging Areaに登録される。

```bash
git add app.js
```

`git add`したあとに同じファイルをさらに編集すると、次の2つは別の状態になる。

```text
Working Tree：git add後に加えた新しい変更を含む状態
Staging Area：git addした時点の内容
```

そのため、追加で編集した内容も次のコミットに含めたい場合は、もう一度`git add`する必要がある。

## Repositoryとは

Repositoryは、コミットされた変更履歴を保存している場所のこと。

Staging Areaに登録した内容を`git commit`すると、変更がコミットとしてRepositoryに記録される。

```bash
git commit -m "Update app.js"
```

## 変更が記録される流れ

ファイルを編集してからコミットするまでの流れは、次のようになる。

```text
Working Tree
  ↓ git add
Staging Area
  ↓ git commit
Repository
```

`git add`は変更をRepositoryへ直接記録するコマンドではなく、次のコミットに含める内容をStaging Areaへ登録するコマンドだと理解した。

# 感想など
* Gitでは、編集中の変更がすぐに履歴として保存されるわけではないと分かった
* Working Tree、Staging Area、Repositoryの3つに分けて考えると、コミットまでの流れを理解しやすかった
* `git add`と`git commit`は役割が異なるため、区別して使うことが大切だと感じた
